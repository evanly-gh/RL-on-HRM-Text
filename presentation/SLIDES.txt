==============================  SETUP (fast)  ==================================

------------------------------- SLIDE 3 (HRM in one diagram) -------------------
[TITLE]
The Model: a Transformer That "Thinks" Before It Writes

[ON-SLIDE]  (use the H/L cycle diagram)
• Standard transformer: one pass through its layers per token
• HRM: a nested RECURRENT loop (High-level + Low-level cycles) runs *before each token*
   → "depth for free": ~8 effective passes from 1B parameters
• PrefixLM attention: reads the WHOLE problem (bidirectional) before writing the solution (causal)

[NOTES ~35s]
"One slide on the model. A normal transformer reads its input once and produces an
answer. HRM instead runs an internal recurrent loop — a high-level and a low-level
module cycling several times — before committing to each token. Think of it as the
model deliberating in its own latent space. It also uses 'PrefixLM' attention: it
reads the entire problem bidirectionally, then writes the solution left-to-right.
Both of these matter because they break the standard tooling, which is our next slide."


------------------------------- SLIDE 4 (Post-training, one slide) -------------
[TITLE]
Two Stages: Teach Format, Then Reward Correctness

[ON-SLIDE]
SFT (supervised fine-tuning)
  • Teach ONE habit: always end with the answer in \boxed{...}
  • LoRA adapter (16.5M params = 1.4%), 1 epoch

DAPO (reinforcement learning from a verifiable reward)
  • Generate 8 solutions per problem → reward = 1 if \boxed{} answer is correct, else 0
  • GRPO + two upgrades: dynamic sampling (drop all-right/all-wrong groups) + clip-higher

The catch: HRM is recurrent + bidirectional → standard tools (TRL, vLLM) don't work → we wrote both loops ourselves

[NOTES ~40s]
"Post-training is two stages. First SFT — we don't teach math, we teach a *habit*:
always put the final answer in a \boxed so a grader can read it. That's a tiny LoRA
adapter, one epoch. Second, reinforcement learning: the model writes 8 solutions to a
problem, each is automatically graded right or wrong by a symbolic math checker, and we
reward the correct ones. We use DAPO, which is GRPO plus two fixes: it throws away
problems where all 8 answers agree — those teach nothing — and it tweaks the clipping to
keep the model exploring. Important practical note: because HRM is recurrent and
bidirectional, the standard libraries everyone uses — TRL for SFT, vLLM for fast
generation — literally don't support it, so we implemented both training loops from scratch."

------------------------------- SLIDE 8 (SFT: reliability) ---------------------
[TITLE]
SFT Bought Reliability, Not Knowledge

[ON-SLIDE]
• Accuracy: 63.5% → ~64%  (unchanged — base already knows the math)
• Format: \boxed{} on RL rollouts ≈ 0.98  → the reward signal is now trustworthy
• 1 epoch only — on purpose: over-training SFT collapses output diversity that RL needs

[NOTES ~35s]
"A quick but important point on SFT: it did NOT raise accuracy, and that's the correct
outcome. The base model already knows the math; what it lacked was consistency. SFT made
the boxed-answer format reliable — about 98% on the RL rollouts — so the reward signal is
trustworthy. We deliberately did only one epoch: train SFT too hard and you collapse the
output diversity that reinforcement learning depends on."

------------------------------- SLIDE 9 (Where can RL help?) -------------------
[TITLE]
Where Can RL Even Help? — Difficulty Matters

[ON-SLIDE]  (bar chart of base solve-rate by level)
   Level 1: 89%   Level 2: 79%   Level 3: 75%   Level 4: 60%   Level 5: 38%
   • Too easy (L1–2): model already gets it → all 8 rollouts right → no signal
   • Too hard (L5):   model rarely gets it → all 8 wrong → no signal
   • Sweet spot (L3–4, & L5 at ~38%): mixed right/wrong → THIS is where RL can learn
   → We built our RL training set from exactly this band (and got 4× the signal vs AIME-level prompts)

[NOTES ~55s]
"So where can RL actually help? RL only learns from problems where the model is
*sometimes* right and sometimes wrong — that's the only case with a usable gradient.
Look at the base model by difficulty: easy problems it always gets, so eight-out-of-eight
correct — nothing to learn. The hardest it almost never gets — eight-out-of-eight wrong —
again nothing to learn. The signal lives in the middle band. We measured this and built
our RL prompt set from exactly that band — Levels 3 to 5 — and it gave us four times the
learning signal compared to our first attempt with competition-level problems that were
just too hard."

[ON-SLIDE]  (reward + entropy curves over steps)

model? That's the finding."

------------------------------- SLIDE 11 (THE FINDING) -------------------------
[TITLE]
Why RL Is Weak at 1B:  pass@1 vs pass@k

[ON-SLIDE]
• RL doesn't TEACH new skills — it SHARPENS skills the model already has
• It raises pass@1 (one try) toward pass@k (best of k tries) — and NO further
• Headroom = pass@k − pass@1.  Big models: huge (correct answers hide in their distribution).
  Small models: tiny — when a 1B model is wrong, it's wrong in ALL tries → nothing to sharpen
• Same lesson as the paper's own ~0.1-point RL gain at this scale

[NOTES ~70s]
"Here's the mechanism. Reinforcement learning from a correct/wrong reward doesn't teach
the model anything new — it can only take solutions the model *already* produces sometimes
and make them more likely. In numbers: it pushes 'one-try accuracy' up toward 'best-of-k
accuracy,' and not a step beyond. So the room to improve is the gap between those two. For
a large model that gap is big — when it's wrong on one try, the correct reasoning is still
hiding somewhere in its distribution, and RL surfaces it. For a 1B model that gap is tiny —
when it's wrong, it tends to be wrong every single time, so there's nothing for RL to
sharpen. This isn't our pipeline failing; it's a property of scale. The HRM authors
themselves only projected about a tenth of a point from RL at this size. The contribution
of our work is making that limit concrete and measurable."

------------------------------- SLIDE 12 (Failures & lessons) ------------------
[TITLE]
Failure Cases & Engineering Lessons

[ON-SLIDE]
• Silent data corruption: a JSON-escaping bug wiped \boxed{} from 88% of our training data → would have zeroed every reward (caught by validation)
• Wrong difficulty: AIME-level prompts → reward stuck at 0.11; matched-difficulty prompts → 0.45
• Generation is the bottleneck: no vLLM for recurrent models → ~25 min/RL step → few steps possible
• Resume bug: silent crash on every checkpoint-resume (found via exit codes, not logs)

[NOTES ~40s]
"Finally, the honest failure reel, because we learned the most here. One: a sneaky JSON
escaping bug had silently deleted the boxed answers from 88% of our training data — that
alone would have made every RL reward zero; we only caught it with a validation assert.
Two: our first RL prompts were competition-level and too hard, so the signal was four times
weaker. Three: the real bottleneck is speed — no fast inference engine exists for recurrent
models yet, so each RL step takes ~25 minutes. These are the practical realities of
post-training a brand-new architecture."


==================================  CLOSE  =====================================

------------------------------- SLIDE 13 (Takeaways) --------------------------
[TITLE]
Takeaways

[ON-SLIDE]
1. We built the first SFT→DAPO post-training pipeline for a recurrent PrefixLM model (from scratch — no off-the-shelf tools)
2. SFT = reliability (format), not knowledge; RL = sharpening, not teaching
3. RL's ceiling is set by scale (pass@k headroom) — and we measured exactly where the signal lives
4. With a fast inference engine (vLLM port → 5–10× rollouts), the RL story is worth revisiting

[NOTES ~25s]
"To wrap up: we built a from-scratch post-training pipeline for this new architecture;
we showed SFT buys reliability and RL only sharpens; and most importantly we pinned down,
with data, why RL is capped at this scale and where its signal actually lives. Give it a
fast inference engine and far more RL steps, and it's worth another look. Happy to take
questions."

----- B4: pass@1 vs pass@k (the math) -----
